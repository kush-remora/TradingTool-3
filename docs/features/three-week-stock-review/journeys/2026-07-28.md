# Three-Week Stock Review

## Feature and purpose

Added a compact stock-review page so Kush can select any NSE equity and inspect its latest three trading weeks before judging a potential Wyckoff accumulation base.

## What was implemented

- Added the **Three-Week Stock Review** navigation entry and route.
- Reused the existing NSE instrument search and stock-detail endpoint; no backend or database change was needed.
- Shows daily date, day, open, close, low, and high for the three latest available ISO weeks.
- Summarises each week with its low/high, the date and day of each extreme, and the weekly range percentage: `(high - low) / low × 100`.
- Includes concise guidance on reading repeated support and range contraction as structural evidence, not a stand-alone accumulation signal.

## Key decisions

- Used the existing 21-session history request to reliably cover three latest trading weeks without introducing a dedicated API.
- Includes the current week once it has trading data, because the page is intended for current review rather than only closed-week backtesting.
- Kept base interpretation manual: volume and delivery remain necessary confirmation under the Wyckoff process.

## Latest daily-candle refresh

The stock-detail endpoint now refreshes a selected symbol's missing daily candles from Kite before serving the review. If the daily provider has not finalised the newest session, it appends the newer live-quote OHLC row. This prevents a stale local candle store from silently limiting the current week to last Friday. If Kite is unavailable, the endpoint continues to serve the available stored history.

Validation: after restarting the local service, `GET /api/stocks/by-symbol/HFCL/detail?days=30` returned the live 2026-07-27 HFCL session (open 200.00, high 200.90, low 191.10, close 192.54, volume 26,152,896).

## Follow-up

- A future iteration can add volume and delivery columns only if the price-structure review proves insufficient for the decision flow.

## Raw-data-first refinement

Kush chose to remove the derived trend/base labels, support/resistance calls, volume warnings, and range-strip visualisation. The screen now deliberately stays minimal: stock selector, weekly low/high/range summary, and daily OHLC values. This keeps the human analysis in control and leaves space to add only genuinely essential raw fields later.

The retained raw table now includes the prior three completed weeks and the latest/current week. It requests 30 sessions to ensure this remains available around market holidays.

## Weekly price-movement timeline

The raw price review remains one table. It retains Date, Day, Open, Close, Low, and High, adding only daily percentage change and accumulated percentage change from the first available trading open of each week. Positive percentages are green and negative percentages red.

The raw table highlights each weekly low session in pale red, each weekly high session in pale green, and a session containing both extremes in pale yellow.

## Three-month deep analysis

The raw table now has a **Show 3 months** toggle below it. It requests 70 trading sessions (approximately three calendar months), expands the table to the available 14 weekly groups, and can be returned to the compact four-week view with **Show 4 weeks**.

## Live market and quick calculator

Added the existing shared live-market widget above the historical review once an NSE stock is selected. It uses the same `NSE:<symbol>` subscription path as the screeners, so it receives SSE updates during market hours and preserves the existing detailed quote drawer.

Added a compact three-field Buy / Sell / Change calculator alongside it. Any valid pair fills the third field: Buy + Sell calculates percentage, Buy + Change calculates Sell, and Sell + Change calculates Buy. Prices are rounded to two decimal places; invalid non-positive prices and a -100% change do not trigger a dependent calculation.

## Floating calculator and complete quote view

Moved the calculator out of the page layout into a compact panel fixed to the lower-right viewport (`position: fixed`). It now remains at the same visible screen position as the raw-data tables scroll, while retaining a narrow-screen width limit. The selected stock's shared live widget now uses `mode="wide"`, exposing its complete O/H/L/V, average-price, volume-ratio, and buy/sell-pressure fields without opening the drawer.

## URL stock selection

The review now accepts a base symbol in `?symbol=` even when Kite lists the NSE equity with a suffix. It first prefers an exact trading-symbol match, then resolves a matching base symbol; `STLTECH` therefore selects `STLTECH-BE` automatically. The focused page test passed (9 tests), and `npm --prefix frontend run build` passed.

## Shared notes table

Added `public.notes` as a generic per-instrument store. Its identity `id` allows multiple notes per stock; `instrument_token` is indexed but intentionally not unique. The table remains independent of the trade journal and includes only `notes`, `created_at`, and `updated_at` alongside those keys. The schema exists both in the base table definition and in migration `20260728_notes.sql`.

## Five-session delivery table

Added a compact table beside the selected stock's wide live-market widget. It shows the five latest stored delivery sessions with date, delivery percentage, delivered quantity, and traded quantity; it uses the established post-market delivery records, so it never presents a live or inferred delivery value.

The existing stock-detail response now carries these five rows in `delivery_days`, keeping the page on its single existing request. Missing source values render as `—`, and no delivery data produces a clear empty state.

## Density refinement

Reduced supporting UI to keep the price review dominant. The floating calculator now has no title and uses three narrower inputs. Notes moved out of the main page into a small floating document button beside the calculator; selecting it opens a compact popover for writing, saving, reviewing, and deleting notes.

The delivery context is now a fixed narrow `Delivery · 5D` table beside Live Market. It keeps five dates and delivery percentage while combining delivered and traded quantities into one concise `Dlv / Trd` column with compact Indian units.

## Note mapper repair

The note API initially failed at runtime because its JDBI constructor mapper depended on camel-case SQL aliases and Kotlin constructor parameter metadata. Replaced that path with an explicit `NoteMapper` that reads the native `id`, `instrument_token`, `notes`, `created_at`, and `updated_at` columns. Both note listing and insert-returning now use this mapper.
