# Absolute Delivery Backtest

## Feature and purpose

Built a six-month event audit for a selectable active institutional grouping, defaulting to `groww_HIGH_QUALITY`. Its purpose is to expose unusually large absolute delivery participation occurring inside an established uptrend without treating the event as a buy signal or mixing in the existing relative-shock scanner.

## Implemented

- Added a pure Kotlin analyzer using only:
  - traded quantity `>= 20,000,000`
  - delivery quantity `> 5,000,000`
  - delivery percentage `> 60%`
- Added `GET /api/strategy/absolute-delivery/backtest`.
- Evaluated every current watchlist symbol against every stored delivery trading date in the six-month window.
- Added explicit `AVAILABLE`, `MISSING_FROM_SOURCE`, `INCOMPLETE`, and `NO_RECORD` states.
- Added a compact React page with matched-event and entire-grouping tabs.
- Added a compact grouping dropdown backed by the active index-constituent catalogue. Changing it reruns the fixed audit for the selected grouping.
- Added mandatory event-date uptrend validation:
  - close above SMA50
  - SMA50 above SMA200
  - SMA50 above its value 20 trading sessions earlier
- Added close/SMA evidence, individual trend gates, combined uptrend result, and explicit missing-candle/insufficient-history states.

## Key decisions and tradeoffs

- Used current active watchlist membership rather than attempting to reconstruct historical membership.
- Used the latest stored delivery date as the backtest endpoint so the report follows available market data rather than wall-clock time.
- Kept the result event-only. No candle loading, price returns, entries, exits, or Wyckoff classification were added.
- Reused the existing index and delivery stores and added no schema or configuration.
- Kept `groww_HIGH_QUALITY` as the default while allowing any current active grouping to be audited.
- Lowered the fixed delivery-quantity floor from 1 crore to 50 lakh; exactly 50 lakh remains an exclusive boundary and therefore fails.
- Calculated SMAs with TA4J from stored daily candles. Each event is evaluated at its own candle index, so later candles cannot influence the result.
- Loaded one batched candle range per selected grouping, with a one-year warmup before the six-month audit window.

## Validation

- Focused React page tests passed (3 tests), covering summary display, both table tabs, missing data, grouping selection/rerun, and the no-match state.

- The production frontend build completed successfully.
