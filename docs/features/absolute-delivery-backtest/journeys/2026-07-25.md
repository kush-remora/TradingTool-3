# Absolute Delivery Backtest

## Feature and purpose

Built a six-month event audit for the current `groww_HIGH_QUALITY` institutional watchlist. Its purpose is to expose unusually large absolute delivery participation for observation without treating the event as a buy signal or mixing in the existing relative-shock scanner.

## Implemented

- Added a pure Kotlin analyzer using only:
  - traded quantity `>= 20,000,000`
  - delivery quantity `> 10,000,000`
  - delivery percentage `> 60%`
- Added `GET /api/strategy/absolute-delivery/backtest`.
- Evaluated every current watchlist symbol against every stored delivery trading date in the six-month window.
- Added explicit `AVAILABLE`, `MISSING_FROM_SOURCE`, `INCOMPLETE`, and `NO_RECORD` states.
- Added a compact React page with matched-event and entire-watchlist tabs.

## Key decisions and tradeoffs

- Used current active watchlist membership rather than attempting to reconstruct historical membership.
- Used the latest stored delivery date as the backtest endpoint so the report follows available market data rather than wall-clock time.
- Kept the result event-only. No candle loading, price returns, entries, exits, or Wyckoff classification were added.
- Reused the existing index and delivery stores and added no schema or configuration.

## Validation

- Focused Kotlin analyzer tests passed, covering exact boundaries, all-three gating, missing-data states, cross-product counts, six-month date resolution, and ordering.
- Focused React page tests passed, covering summary display, both table tabs, missing data, and the no-match state.
- The Maven dependency chain through `service` compiled successfully.
- The production frontend build completed successfully.
- General and Kotlin-specific review gates found no critical or high-severity issues.
