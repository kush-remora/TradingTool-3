# Target Outcome Reporting

## Why

CSV backtesting must measure whether a configured target was reached, not whether an exit happened to be profitable.

## Implemented

- Added an explicit target-hit outcome to CSV backtest exits and trade results.
- Replaced monthly Win/Loss/Win Rate with Target Hit, Stop Hit, Unresolved, and Target Hit Rate.
- Updated the filtered Trade Details summary to use the same target-driven definition.
- Moved V2 Vol Spike and V2 Run % to Trade Details columns 5 and 6.
- Routed CSV backtest and review requests through the production API client instead of GitHub Pages-relative URLs.

## Decision

An exit at the maximum holding period or an open trade is unresolved even when it has positive P&L. Only a target exit is a success.

## API Deployment Fix

GitHub Pages cannot serve the backend under its own `/api` path. CSV backtest and review pages now use the shared API client, which resolves production calls to Render. The committed Render and service defaults now use `https://kush-remora.github.io` as the GitHub Pages origin.

Validation: the live Render review-reasons endpoint returned JSON with that origin allowed; focused CSV frontend tests, the frontend production build, and the Maven service package all passed.
