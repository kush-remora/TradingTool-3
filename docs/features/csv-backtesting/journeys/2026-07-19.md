# CSV Backtesting: Daily Candle Rule Correction

## Why This Was Built

The CSV backtest must evaluate Chartink fresh-breakout signals using the next trading day's open for entry, with the daily low taking stop-loss precedence over the daily high target when both occur in one candle. It must also support combined signal rows from several uploaded index CSV files.

## Plan

- Test the daily-candle exit rules, including the entry candle.
- Keep candle loading and API contracts unchanged.
- Extend the existing console uploader to combine selected CSV files before it runs the backtest.

## What Was Implemented

- Added a small, pure fixed-exit evaluator used by the existing CSV backtest service.
- The evaluator starts with the entry candle, checks gap exits first, then evaluates the daily low before the high. A candle touching both thresholds therefore exits at the stop price.
- The CSV console now accepts multiple files and combines their data rows before posting one request to the unchanged backtest endpoint.

- `mvn -pl service -am -DskipTests compile` — passed.
- `cd frontend && npm run build` — passed.

## Follow-up

Use the **CSV Backtest Tool** page to select `freshbreakout.csv` and any index files, set Fixed Target & SL percentages, and run the combined result.

## 2026-07-20: Breakout Retest Entries and Target + Trailing Stop

### Why

Daily breakouts can revisit their breakout level before a sustained move. The backtest needs to compare that entry timing without treating a memorised 5-7% drop as a universal rule. Trailing-stop trades also need a defined profit target.

### What Changed

- Added next-day-open, breakout-retest, and confirmed-retest entry rules.
- Retests use the prior 20-session high as the breakout level and a configurable retest window and tolerance.
- Added the chosen entry rule and calculated breakout level to each trade result.
- Target percentage is now required for both fixed-stop and target-plus-trailing-stop modes.
- A trailing trade exits at its target as soon as price reaches it; otherwise its stop ratchets after each completed candle close.

### Decisions and Validation

- Retest fills use daily-OHLC attainable prices; confirmed entries wait for the following open, avoiding look-ahead.
- Stop/target collisions remain stop-first because daily candles cannot establish intraday order.

- `mvn -pl resources -am -DskipTests compile` — passed.
- `npm run build` in `frontend` — passed.

## 2026-07-20: First-Five-Session Dip Measurement

### Why

Measure how far a signal falls immediately after entry, including trades that later rally, to test the observed breakout-pullback behaviour.

### What Changed

- Trade results show the lowest price across the entry session and four following trading sessions.
- They also show the entry-to-low rupee difference and positive drop percentage.
- Monthly summaries show the average five-session drop percentage.

### Decision

The five-session observation window is independent of the simulated exit. This preserves the early-price-behaviour data even when the configured target or stop closes the trade first.

## 2026-07-20: V2 Breakout Validation

### Why

Allow the existing CSV backtest to measure a stricter fresh-breakout subset against the V1 baseline, without creating a separate console or changing the established entry and exit simulation.

### What Changed

- Added an optional **Apply V2 breakout validation** switch to the CSV Backtesting Engine.
- A signal passes only when it is a fresh strict 100-session high, has one pre-breakout session at least 2× its own prior 20-session average volume, and its breakout close is no more than 6% above the previous close.
- The table shows the largest qualifying pre-breakout volume ratio, count of separate 97%-to-below-resistance failed attempts, the six-close recent base, and move from that base.
- The result header displays submitted signals and V2-passing signals. V1 remains unchanged while the switch is off.

### Key Decisions

- Existing console instead of a new screen: it makes V1 and V2 comparisons immediate and avoids a second upload/backtest flow.
- V2 uses roughly 450 calendar days of history before a signal because freshness requires testing earlier breakout events against their own 100-session histories.
- Failed attempts count contiguous near-resistance sessions once, and exclude the exact historical resistance high itself.

### 2026-07-20: Client-Side V2 Run Filter

- It immediately hides trade rows whose move from the six-close base exceeds the selected threshold, without rerunning the backtest.
- The control is disabled for V1-only result sets because they have no V2 run metric.

### 2026-07-20: Two-Green-Candle Entry and Early Red Count

- Added `2 Green Candles` to the existing entry-rule selector to compare it directly with next-day open and retest entries.
- The breakout candle is green when its close exceeds the prior close. The scanner waits up to 20 sessions for the second close-up candle and buys at the open of the following session; the earliest possible entry is T+2 open.
- Added `3D Red Candles`: the number of close-down sessions on the buy day and the next two sessions.
- Retest settings now appear only for retest entry strategies.
- Validation: focused CSV-backtest Kotlin tests, `mvn -q -pl resources -am -DskipTests compile`, and `npm --prefix frontend run build` passed.

### 2026-07-20: Configurable Extension Guard

- Added **Maximum close-to-close gain %**, defaulting to 6%, to the existing backtest form.
- The same value guards the V2 breakout day and both required candles in `2 Green Candles` entry mode.
- A confirmation day above the cap is not allowed to create an entry; this excludes the GMDCLTD 16-Apr-2026 +20% confirmation case at the default setting.
