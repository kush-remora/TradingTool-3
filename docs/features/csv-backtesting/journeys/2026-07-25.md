# CSV Backtesting: Sector Table Filter Fix

The Trade Details sector filter did not reliably update the visible rows because the page duplicated Ant Design's filter state in both a custom dropdown and an external data filter.

The table now uses Ant Design's native tree-mode filter and row predicate as the single source of truth. Tree mode provides a real Select All checkbox that checks every sector while preserving filter search. The Maximum V2 Run filter excludes rows without a V2 metric whenever a limit is active, as well as rows above the limit. V2 now finds its run base using the lowest low in the previous 50 trading sessions, then averages the six closes ending on that low. Validation: focused V2 validator tests and the production frontend build completed successfully.

The Trade Details table now includes **Breakout Day Move %**. It is calculated from the signal-day candle only: `(close - open) / open * 100`, so it remains independent of the selected entry strategy. The value is returned for both entered and unfilled signals, when the signal candle is available.

## Duplicate-row and combined-filter correction

A live duplicate fixture exposed the deeper failure: duplicate symbol/date signals generated duplicate response rows, while the table also used symbol/date as its React key. Changing Maximum V2 Run then caused React to retain excluded rows and duplicate other rows.

- Deduplicate backend signals by symbol and signal date before validation, trade generation, and summaries.
- Defensively deduplicate frontend rows and give each row a stable identity.
- Memoize the table data and sector options so a V2 maximum does not churn filter inputs.
- Synchronize the displayed count with both Maximum V2 Run and selected sectors.

Validation:

- CSV-backtest core tests: 18 passed.
- CSV backtest frontend tests: 5 passed.
- Frontend production build: passed.
- Live combined-filter check: Maximum V2 Run 15% plus Healthcare showed only SUNPHARMA and `Showing 1 of 3 trades`.

## Filtered SL outcome line

Added a compact result line that recomputes from the rows matching both Maximum V2 Run % and the sector table filter. It reports filtered total, SL Yes, SL No, and success rate, where success rate is the percentage of filtered rows whose SL value is No. This keeps the metric aligned with exactly what the user sees in Trade Details.

Validation: 6 focused frontend tests passed, including mixed and empty SL outcomes, and the production frontend build passed.

## Forty-day maximum holding period

An entered trade now has a maximum holding period of 40 calendar days. If the configured target or stop loss has not already exited the trade, the engine closes it at the close of the first trading candle on or after entry date plus 40 days. The ordinary stop and target checks retain priority on that day. This applies to both fixed-target and trailing-stop backtests.

Validation: focused fixed and trailing exit evaluator tests passed.

## Breakout delivery context

Trade Details now displays two delivery-only context columns from the persisted NSE delivery history: **Breakout Delivery %** for the signal date, and **T−5 Max Delivery %** for the five completed trading sessions before it. Missing source rows remain blank. These measures do not change trade selection, entry, or exit behavior.

Validation: focused delivery-metric test, CSV table tests, Kotlin service compilation, and production frontend build passed.
