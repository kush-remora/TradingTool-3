# EY Visual Book Generator Working Agreement

These rules apply to this EY project and override the normal autonomous delivery pace.

1. Work in small, independently reviewable tasks only.
2. Before starting a task, explain the proposed outcome, files or systems affected, and how it will be checked.
3. Discuss the task with Kush and obtain explicit agreement before making changes.
4. Complete only the agreed task. Report the result and evidence, then wait for Kush's review before proposing or starting the next task.
5. Keep `task.md` current so the overall sequence remains visible.
6. For every substantive new discussion, use the Elephant-Goldfish Model (EGM) workflow when its skill is available. If it is unavailable in the current runtime, state that clearly and preserve the same discussion and approval gates manually.
7. Never put API keys or other credentials in tracked files, browser code, logs, or chat output. Use ignored local environment files and Render secrets.
