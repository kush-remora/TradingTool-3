# EY Visual Book Generator Working Agreement

These rules apply to this EY project and override the normal autonomous delivery pace.

## Authoritative product contract

The product is an AI-assisted document transformation tool for the handoff between a documentation/content team and a visual designer. A user uploads a source PDF/document and visual asset(s), then explicitly selects the level of authority Gemini is allowed to have:

- **Preserve:** do not change the source text, language, order, structure, or formatting. Visual insertion is allowed only where it does not violate that protection; otherwise the product must surface the conflict.
- **Restructure:** preserve the source language and meaning, while allowing new headlines, subheadings, numbered lists, section ordering, hierarchy, and formatting.
- **Transform:** allow full editorial and design authority: summarize, rewrite, create new structure and headlines, integrate visuals, and produce genuinely different layouts.

These are permission levels, not style presets. The selected mode must choose a corresponding Gemini prompt and constrain the output and validation. The product is not just a PDF beautifier or a layout generator. Its core value is controlled transformation of source content with an explicit boundary between preserving, restructuring, and rewriting.

Intended flow: upload source document and visual asset(s) → choose a mode → send the mode-specific Gemini prompt → receive structured content/layout output → validate against the mode's rules → preview and export. Preserve requires verification against the source; prompts alone cannot guarantee that the original document was unchanged.

The canonical prompt contracts live in `config/gemini-prompts/`. Read the matching prompt file and its README before changing Gemini request construction, response schemas, or authority-mode behavior. Do not replace these contracts with ad hoc prompt strings embedded in application code.
