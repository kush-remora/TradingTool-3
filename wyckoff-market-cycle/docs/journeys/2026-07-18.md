# Chartink Evidence Intake and Dashboard

## Why

Provide one simple, inspectable place to load the seven daily Chartink evidence files and keep curated-watchlist candidates visible first.

## Implemented

- `chartink_scan_events` stores validated historical scanner hits.
- Fixed uploads: four Accumulation universes, Phase D, T2 High, and Fresh Breakout.
- CSV validation, duplicate reporting, universe filtering, and atomic replacement per upload scope. Both `dd-MM-yyyy` (Chartink export) and ISO dates are accepted.
- Upload responses list skipped symbols with a reason and their current base universe when known, so universe differences can be investigated.
- Each upload card shows its latest uploaded filename and time; candidate evidence can be viewed by Nifty 100, Midcap 150, Smallcap 250, or Microcap 250.
- Combined dashboard with 1, 2, 3, and 9-month filters, latest source dates, and curated-watchlist badges.

## Decisions

Curated watchlists are read live from active `index_constituents` memberships outside the four Nifty universe keys. They improve review priority only; they never create an event. Cash scans keep only symbols in a configured Nifty universe.

## Validation

- Core service tests cover valid replacement, invalid headers, duplicates, outside-universe cash rows, time filtering, and watchlist ordering.
- Frontend page test verifies seven fixed slots and evidence rendering.
- Kotlin package and frontend production build pass.

## Forward accumulation replay

- Added persistent manual Forward runs with daily base snapshots for 1, 3, 6, and 9-month universe replays.
- Shape outcomes are explicit: `VALID`, `NEEDS_REVIEW`, or `INVALID`. Ambiguous/curvy structures are stored as `UNCLASSIFIED` for manual feedback, never silently promoted.
- Re-running the same universe, period, and evidence end date replaces the derived run; a newer Accumulation upload marks prior results stale until rerun.
