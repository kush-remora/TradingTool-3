# Chartink Evidence Intake and Dashboard

## Why

Provide one simple, inspectable place to load the seven daily Chartink evidence files and keep curated-watchlist candidates visible first.

## Implemented

- `chartink_scan_events` stores validated historical scanner hits.
- Fixed uploads: four Accumulation universes, Phase D, T2 High, and Fresh Breakout.
- CSV validation, duplicate reporting, universe filtering, and atomic replacement per upload scope. Both `dd-MM-yyyy` (Chartink export) and ISO dates are accepted.
- Upload responses list skipped symbols with a reason and their current base universe when known, so universe differences can be investigated.
- Each upload card shows its latest uploaded filename and time; candidate evidence can be viewed by Nifty 100, Midcap 150, Smallcap 250, or Microcap 250.
- Combined dashboard with 1, 2, 3, and 9-month filters, latest source dates, and curated-watchlist badges.

## Decisions

Curated watchlists are read live from active `index_constituents` memberships outside the four Nifty universe keys. They improve review priority only; they never create an event. Cash scans keep only symbols in a configured Nifty universe.

## Regression shape detection correction

- The percentage-based Flat and Golden Flat classifier was removed because it did not follow the Hybrid Validation Pipeline's quadratic-regression design.
- After chaining Accumulation hits at the 15-session gap, the final hit anchors a 60-trading-session close-price window. The window is classified by normalized quadratic regression (`y = ax² + bx + c`): flat, cup, downward drift, upward drift, or inverted-U distribution.
- Regression curvature and slope, the original hit dates, and the actual 60-session base dates are stored in the existing snapshot JSONB details. BHEL's 60-session reference window ending 2026-03-30 is a valid downward drift regression fixture.
- Replays can still be saved for 1 day, 1 week, 1, 3, 6, or 9 months. A run persists its explicit period and replaces only the matching universe/period/date scope.

## Turning-point decision metrics

- A positive quadratic curvature is no longer enough to call a shape a Cup. The regression must slope down at the start, slope up at the end, and have its fitted lowest point within the 60-session window. The reverse makes an inverted-U `INVALID`; curved but monotonic structures remain upward or downward drift.
- Snapshot JSONB now stores curvature, center slope, left/right edge slope, and turning-point position. Slopes are normalized percentage change per 10 sessions, which is stable across chart zoom levels; the main and detail tables display a compact value with a hover explanation.
- Algorithm version `v5-quadratic-turning-shapes` deliberately marks older calculations stale, so their old broad Cup labels are never mistaken for the stricter decision.

Validation: focused Kotlin shape tests (including monotonic curve rejection), core package, focused frontend page tests, and frontend production build passed.

## Stock-block confirmation sorting

- Phase D is now the default descending table sort. It ranks one stock by its latest Phase D, then keeps all bases for that stock contiguous so its historical progression can be read together. For a `+n` value, the displayed date is that same latest date.
- Within a stock block, the newest base appears first for this descending review order. The compact `Group stocks` toggle defaults on; turning it off restores raw row-level confirmation sorting.
- No API, database, or replay result changed. This is a presentation-only review aid.

Validation: focused Forward Accumulation page tests and frontend production build passed.
