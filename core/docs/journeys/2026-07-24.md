# Weekly Floor Rebound Backtest v1

## Weekly Base Definition

Added a separate Base Definition screen and API that do not create trades. For every analysis date, it uses the three previous completed ISO weeks, extracts one weekly low from each, and creates a zone from their minimum and maximum. The base is valid at a zone width of 2% or less. The API returns each daily check with the three source weeks and lows so the calculation can be audited. It analyses the latest 200 trading sessions using cached Kite NSE daily candles.

A valid base must additionally have its evaluation-day close inside the configured 200-SMA fair-value band. The root JSON configuration sets the initial range to −15% through +15%, and the table exposes the SMA and distance for auditability.

## Base Rebound Group Backtest

Added a third, backtest-only screen that selects existing index-constituent groups and runs every member through the 200-session base-rebound replay. Each symbol uses the same JSON-configured base and SMA checks, enters only after a same-day 1% rebound from a valid-zone touch, and holds until a 5% target or the end of available data. The UI groups results by index and expands each stock to its trade audit rows.

## Why

Test the hypothesis that a stock with three tightly aligned weekly lows, a prior decline, and a recovery through the floor can produce a positive one-week swing. This is a price-structure experiment, not a claim of confirmed Wyckoff accumulation.

## Delivered

- Added a Kotlin weekly-floor rebound engine and candle-loading service.
- Added `POST /api/strategy/weekly-floor-rebound/backtest` for a selected NSE equity.
- Added a searchable Kite-instrument UI page with NETWEB as the default.
- The report covers the latest 200 completed trading sessions, with 252 earlier sessions used only for 52-week context.
- Trade rows include rejected/no-entry weeks as well as fills, exits, gross returns, and gap/ambiguity flags.

## Rules and Tradeoffs

- Floor: the three immediately prior completed ISO weeks must have lows within 2%.
- Entry: first trading day reaches 1% above the floor; a gap fills at the opening price.
- Stop: 0.5% below the floor. Target: 5% above actual entry. Unresolved trades exit at the final close of that week.
- Daily bars that hit both stop and target exit at the stop. A stop gap exits at the opening price.
- V1 deliberately reports gross returns only. Charges and slippage are deferred until the raw price hypothesis has earned that complexity.

## Zone Ledger Override

The original rolling three-week floor was replaced with frozen, overlapping-zone deduplication. Each support zone has its own creation date, range, test low, and lifecycle outcome. A zone waits for a later price touch, then requires a 1% rebound from the observed test low. Zones expire from automatic trading after eight weeks but remain visible as historical support.
## Manual frozen support-zone backtest

The Weekly Floor Rebound screen now separates zone selection from trade execution: the user supplies one support floor, ceiling, and activation date. Each later trading day is audited independently. A trade enters on that same day's low plus 1% when the low is inside the zone; daily OHLC is interpreted optimistically as low before high, so the target may be hit on the entry day. The only exit is a 5% target; there is no stop-loss or Friday exit in this version.

The trade table labels the repeated date as `Active from`, which is intentionally identical for all trades using the same frozen zone. It also shows the number of trading sessions from entry through the target date (zero when target is reached on the entry candle). Daily validation data now contains every active daily candle, including those while an earlier trade is open.
