# 2026-08-18 — Quality Gate Redesign + Entry Gap Guard

## Feature
Redesigned `BreakoutDayQualityAnalyzer` from a single-candle poison model to a 4-check lookback scoring model. Added selectable entry triggers, a `maxEntryGapPct` entry-gap guard, and per-trade quality context to the backtest.

## Why It Was Built
Data from the 6-month Core watchlist backtest (50 trades) proved the old quality gates were broken:
- REJECT trades won 55.3%, PASS trades won 50% — zero predictive value
- Root cause: "one REJECT poisons all" + loose thresholds → 76% of all trades tagged REJECT by default
- Entry chasing was the real hidden risk: the first later tradable open averaged +1.48% above breakout close; >3% gap = 33% WR

## What Was Implemented

### `BreakoutDayQualityAnalyzer.kt` — full rewrite
Old: 6 checks (close position, volume ratio, delivery ratio, breakout-line clearance, extension, climax spread) — all on the single breakout day — "one REJECT poisons all".

New: 4 checks with PRE-BREAKOUT CONTEXT (last 5 sessions before breakout day):

| Check | Key | What it measures | PASS |
|---|---|---|---|
| Buyer days | `buyer-days` | Sessions where close > open in last 5 | ≥4/5 |
| Close position trend | `close-position-trend` | Avg close position % last 5 sessions | ≥65% avg |
| Volume dry-up | `volume-dry-up` | Last 5D avg vs prior 10D avg (Wyckoff LPS) | ≤0.85× baseline |
| Breakout day close | `breakout-day-close` | Close position % on breakout candle | ≥75% |

**Scoring (no more single-REJECT poison):** PASS count ≥3 → PASS, =2 → WAIT, ≤1 → REJECT. UNAVAILABLE checks are excluded from the denominator. Delivery remains context-only because breakout-day volume changes its denominator.

### `AdaptiveBreakoutBacktestModels.kt`
- Added `maxEntryGapPct: Double = 2.5` to `AdaptiveBreakoutBacktestRequest`
- Added `SKIPPED_ENTRY_GAP` to `AdaptiveBreakoutBacktestExitReason`
- Added `entryGapPct: Double?` to `AdaptiveBreakoutBacktestTrade`
- Added `skippedEntryGapCount: Int` to `AdaptiveBreakoutBacktestSummary`
- Added `qualityChecks: List<BreakoutQualityRuleResult>` to trade for per-check analysis
- Renamed the backtest summary count to `signalCount` and added the selected `entryTrigger` to keep reclaim runs from being labelled as fresh breakouts.

### `AdaptiveBreakoutBacktestEngine.kt`
- Gap guard: if the first later tradable open exceeds `breakout close × (1 + maxEntryGapPct/100)` → `SKIPPED_ENTRY_GAP` (trade recorded but not counted in `enteredTradeCount`, position lock not advanced)

### `AdaptiveBreakoutScannerService.kt`
- `maxEntryGapPct` wired through `runBacktest` → `runStockBacktest` → `runWatchlistBacktest` → engine and rejected when negative.

## Key Decisions / Tradeoffs
- Kept `ChartContextAnalyzer` untouched — it's a separate gate used for the buy review console, not the core quality score
- `SKIPPED_ENTRY_GAP` trades are still recorded in the trade list (not silently dropped) so you can see how many entries the gap guard protected you from
- Default `maxEntryGapPct = 2.5` — data showed >3% gap = 33% WR, 1-3% = 75% WR
- UNAVAILABLE checks (missing delivery, insufficient history) are excluded from denominator rather than counted as REJECT — fairer to data gaps
- Delivery is displayed as raw `delivPer` plus delivered-quantity context; it is not a scored check.

## Validation
- `BreakoutDayQualityAnalyzerTest`: 10 tests pass (rewritten for new model)
- `AdaptiveBreakoutBacktestEngineTest`: 6 tests pass (4 updated + 2 new gap-guard tests)
- Frontend review fixtures were updated to the four-check response contract. Full frontend test runs still include unrelated timeout/CSS failures; the focused buy-review test is the relevant regression check.
