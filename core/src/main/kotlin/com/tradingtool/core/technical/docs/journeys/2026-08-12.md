# Fresh breakout dates

## Why

The compact stock console needs one reliable date for the latest fresh close-confirmed breakout at four common horizons: 20, 50, 52, and 100 trading sessions.

## Implemented

- Added `calculateFreshBreakoutDates` in the core technical package.
- A breakout is recorded when the close crosses above the prior N-session high.
- Continuation closes stay part of the same event; a new event is allowed after the close returns to or below that day’s rolling N-session high and later crosses above it again.
- Exposed nullable ISO dates as `breakout_dates` on the stock-detail response.
- Extended each horizon with the prior rolling-high level that was crossed, so the UI can show current distance from the breakout level.

## Decisions

This is an evidence field, not a buy signal. The calculation uses close confirmation and session lookbacks so the UI can distinguish a new breakout from a stock simply remaining above its prior range. Resetting against the original breakout level was rejected because it left NETWEB’s 2023 event active through 2026.

## Validation

- `mvn -pl core -Dtest=FreshBreakoutDatesTest test` — passed (4 tests).
- Breakout-level assertions now verify the crossed prior rolling high is returned with each date.
- `mvn -f pom.xml -pl service -am package -DskipTests` — passed.
- Live `NETWEB` stock-detail response returned current dates: 20D `2026-08-04`, 50D/52D/100D `2026-06-18`.
