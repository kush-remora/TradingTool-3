# Delivery Breakout Validation — 2026-08-23

## Why it was built

The user wanted to run Delivery Breakout Validation against multiple watchlists in one action instead of repeating the scan for each watchlist.

## Implemented

- Added `GET /api/strategy/delivery-breakout/dashboard/multi?watchlistKeys=key1,key2`.
- Preserved the existing single-watchlist dashboard endpoint.
- Added bounded concurrent execution with up to three watchlists running at once.
- Returned successful dashboards plus per-watchlist errors so a partial failure does not hide valid results.
- Added a multi-select watchlist control, aggregate summary counts, source-watchlist table attribution, and multi-watchlist CSV export.
- Added event-day high/low to the dashboard contract and a compact Price Context table cell with live LTP, event close, LTP-to-event movement, event-day range, previous-close-to-event movement, and close-near-high position.

## Key decisions

- Detection logic remains unchanged: the existing 10-session delivery/volume event scan is reused for every selected watchlist.
- The UI uses the single endpoint for one selection and the multi endpoint for two or more selections.
- Rows carry their source watchlist in the frontend display/export model so duplicate symbols from different lists remain distinguishable.
- Price Context sorting uses the existing `close_pct_change` value, which represents previous close to event-day close; the UI does not sort on live quote movement.

## Validation

- Delivery Breakout frontend tests cover the existing single-watchlist flow and the multi-watchlist selection flow.
- Frontend production build and backend compilation are required before delivery.
