# Momentum Scanner v1 — 2026-08-07

## Why it was built

The existing Three-Week Stock Review needed a compact, objective way to surface momentum candidates without turning the tool into a buy/sell recommendation engine. The feature is designed to reduce watchlist research time while keeping the underlying price and volume evidence visible.

## What was implemented

- Added a reusable Kotlin momentum-evidence calculator for 200 DMA position, four completed weekly close-to-close returns, and all daily volume events at least 2.0× the prior 10-day average over the last 90 days.
- Added explicit `AVAILABLE`, `INSUFFICIENT_HISTORY`, and `NO_CANDLES` data states.
- Attached the same evidence model to the existing watchlist weekly-review response and single-stock detail response.
- Added a compact momentum evidence strip and `Above 200 DMA` filter to the Three-Week Stock Review + Current Week watchlist screen.
- Added a detailed Momentum Evidence panel with raw participation-event rows to the single-stock Three-Week Review.
- Added the latest 252-session high and distance from that 52-week high to the shared evidence model and both review surfaces.
- Replaced the compressed participation label with "High-volume days" plus the prior 10-day average-volume definition.
- Added the actual high-volume event dates to the compact summary so the count is directly actionable without opening the detailed table.
- Added a separate high-volume event table with date, close, traded volume, volume multiple versus the prior 10 trading sessions, delivery percentage, daily return, and price change since the event.
- Made the 90-calendar-day event lookback visible in the summary and table heading.
- Reused the same event table in the watchlist card behind a compact `Volume events` disclosure, so the scan surface exposes the raw event data without making every card permanently tall.
- Added event age in days, current LTP/latest-close reference at the top of the event table, and each event's percentage distance from that reference price.

## Key decisions and tradeoffs

- Reused the existing watchlist and stock-review routes instead of adding a duplicate scanner page.
- Fetched the longer history server-side while preserving the existing 60-day daily payload for the watchlist page.
- Kept the threshold as a named code constant for v1 simplicity; historical validation can determine whether it needs runtime configuration.
- Matched the existing stock-detail convention by defining 52-week context as the latest 252 available trading sessions and using daily highs, while measuring distance from the current close.
- Did not add a score, ranking model, RSI, Wyckoff classification, or recommendation language.
