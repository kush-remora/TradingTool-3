# Summary Console

## Why

The Summary Console provides one daily attention view across one or more selected watchlists. It identifies objective market events and routes the user to Kite or the existing Three-Week Stock Review + Current Week page for interpretation.

## Implemented

- Added `/api/strategy/summary-console/watchlists` and `/api/strategy/summary-console/scan`.
- Unioned selected watchlists and de-duplicated stocks by symbol.
- Added 200 SMA range crossing, greater-than-3% close-to-close movement, 2x prior-five-session volume, delivery percentage, and 20/40/60-day closing-level breakout signals.
- Kept both breakout states for every window: intraday high crossing the prior highest close and close confirmation above that level.
- Added the React Summary Console route with multi-watchlist selection, event-only rows, Kite stock links, and Detail actions.
- Added an AI-friendly CSV export with explicit snake_case headers and a companion Markdown guide explaining every column and its purpose.
- Added a visible column guide and a suggested prompt for selecting the top five stocks for deeper research without turning the output into a buy/sell recommendation.
- Changed the scan from one session to the latest five completed trading sessions. Each event is evaluated against that day's prior-session baselines and emitted as its own stock/session row.
- Added a client-side filter builder with signal selection, `Any`/`All` matching, and same-session versus across-five-session scope. Cross-window `All` matching permits required signals on different dates and preserves all event rows for qualifying stocks as context.
- CSV export now uses the rows currently visible after filtering.

## Decisions

- Baselines use only preceding completed sessions.
- A stock appears when at least one event is triggered; non-triggered columns remain visible as context.
- The 200 SMA is calculated from the preceding 200 closes and tested against today's full range.
- Delivery percentage is displayed as context and is not used as a gate.
- The same stock may appear on multiple session dates; the table and CSV preserve those dates instead of combining signals from different days.
- Filtering is deliberately client-side because the existing five-session response already contains the complete event rows needed for both same-session and cross-window queries.
