# Wyckoff Raw Observation V1

## Why it was built

The investing scanner needs to surface orderly price and volume behavior for human Wyckoff review. It must not pretend that code can reliably identify accumulation or Phase D from a long list of rigid rules.

## What was implemented

- A Kotlin engine that produces daily OHLCV observations for one stock or a watchlist.
- Transparent ATR, ATR percentage, true-range-to-ATR, volume-versus-20-session-average, and 20-session price-change fields.
- Transparent 20-session range and prior 20-session high fields for validating range containment and breakout prompts.
- Summary fields for period return, high/low, ATR context, and average volume.
- Candidate timeline periods and day annotations for prior decline, candidate accumulation, orderly advance, and possible Phase D.
- API endpoints for watchlist options and raw observations.
- A frontend page with watchlist/stock selection, 3/6/12-month lookbacks, summary rows, and expandable daily tables.

## Key decisions and tradeoffs

- No score, pass/fail, accumulation verdict, phase label, 200 SMA, or entry rule in V1.
- Candidate labels are prompts only. A possible Phase D starts when price closes above the prior 20-session high with range or volume expansion, then remains a prompt only while price holds above that level.
- Candidate accumulation is intentionally simple: a contained 20-session range with a modest net price change. It is not confirmation of institutional accumulation.
- ATR is currently a simple rolling 14-session average of true range so the number is easy to inspect. This can be replaced with Wilder smoothing later if the raw output proves useful.
- The service uses existing active NSE constituent data and candle-cache paths rather than creating a second universe or data-ingestion path.

## Validation

- `mvn -q -Dkotlin.compiler.execution.strategy=in-process -pl core -am -Dtest=WyckoffRawObservationEngineTest -Dsurefire.failIfNoSpecifiedTests=false test` passed.
- `mvn -q -Dkotlin.compiler.execution.strategy=in-process -pl service -am -DskipTests compile` passed.
- `npm run build` in `frontend` passed.
- The focused engine test now covers a synthetic decline, stable range, and expansion/follow-through sequence.

## Next follow-ups

Use real watchlist output and chart review to identify missing raw fields. Candidate additions include a 200 SMA distance, volume trend context, or a clearer price-contraction measure, but none should be added until the first output review shows a concrete need.
