# Volume Event Confirmation Backtest — 2026-08-10

## Why it was built

The volume-event backtest needs one compact, execution-focused view: every qualifying volume-shocker signal becomes a trade row with its entry, target, status, holding days, and current performance.

## What was implemented

- Replaced the unresolved-only close return with `currentLtp` and `currentLtpChangePct` on volume-event trade observations.
- Uses the latest available candle close at the backtest end date as the historical Current LTP reference.
- Populates both values for target-hit and unresolved entered trades; rejected audit observations remain non-trades and keep these fields empty.
- Added engine coverage for target-hit, open, and rejected price-confirmation cases.
- Made the volume-shocker price-confirmation rule the only backtest contract; the service now accepts multiple watchlists and an editable target percentage defaulting to 10%.
- Reworked the UI into a compact six-month trade table with Current LTP and percentage change from entry for every entered trade. Open trades keep the current price, remain open, and do not receive an exit date or exit price.
- Requires the signal day itself to be a new volume shocker and records it separately from the previous reference shocker date. Entry occurs at the next session open.
- Checks the target through the backtest end date instead of expiring the trade after 15 holding sessions; an unhit target remains open.
