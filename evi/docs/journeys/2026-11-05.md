# EVI Authority Generation — 2026-11-05

## Why it was built

The original EVI flow treated every request as a layout-only generation task. The product contract now requires explicit AI authority selection: Preserve, Restructure, or Transform.

## What was implemented

- Added the `AuthorityMode` model and a new `POST /api/visual-book/authority` backend path.
- Added runtime loading of the canonical contracts from `evi/prompts/`.
- Added prompt placeholder rendering, mode-specific response-schema loading, and lightweight mode-payload validation.
- Added request limits, rate limiting, and a 60-second Gemini request timeout.
- Added a frontend authority selector and a structured contract-result preview.
- Removed the legacy layout-options flow, layout-only API, and layout-specific frontend renderer so authority mode is now the only generation path.
- Updated Preserve to require exactly two additive page-placement variants (image before or after source) and render those choices as visual cards instead of raw Gemini JSON. The original PDF page is rendered unchanged; the image is added as a separate page.
- Added a PDFBox-backed source-page image endpoint and changed the Preserve preview to compose that immutable page image with the selected visual page. The preview no longer reconstructs the source page from extracted text.
- Added a structured Restructure preview that renders synthesized hierarchy, verbatim source nodes, coverage, and visual placement without exposing raw Gemini JSON.
- Added a structured Transform preview with two selectable variants, visible archetype/grid differences, rewritten content, visual roles, grounding IDs, and summarization audit notes. The UI only accepts exactly two parsed variants for selection.
- Synced the authority-mode preview into the root frontend route used for local testing, making `http://localhost:5173/TradingTool-3/book-generator` the single development entry point instead of requiring the separate EVI port.
- Repositioned the first screen as an EY internal EVI document studio: the visible brand, headline, saved-project labels, creation brief, and workflow steps now describe enterprise source-document visualization rather than a personal story/home.
- Registered the authority resource and service in the root Dropwizard application so the browser can reach the new endpoint.

## Decisions and tradeoffs

- The authority-aware path replaces the old layout-only preview; the legacy layout API, service, and renderer are removed.
- The current frontend supplies one page-text block and image metadata; it does not yet send full document structure or image bytes to Gemini.
- Preserve fidelity, Restructure lexical preservation, and Transform factual grounding still require deterministic application-side validation beyond the current response-envelope checks.

## Validation

- `npm run build` in `evi/frontend` passed.
- Prompt schemas and required placeholders were parsed successfully with a Node validation script.
- Maven packaging passed using IntelliJ's bundled Maven executable.
- The full preflight now returns `200 OK` with the expected CORS headers, and a real `POST /api/visual-book/authority` probe returned a valid `PRESERVE` response from Gemini.
- The targeted EVI Maven tests pass after the legacy layout tests were removed.
- The live service exposes `GET /api/folios/{id}/pages/{pageNumber}/image`; invalid IDs return `400`, and the authority preflight remains `200`.
